# Apple Watch: предупреждение при погасшем экране

Связка: iPhone 11 (iOS 27.2.1) + Apple Watch SE 1-го поколения (watchOS 10.6.2). Версия приложения часов 1.0 (сборка 2).

## Что было не так

Приложение часов работало только пока было на экране. Через несколько секунд после опускания руки watchOS приостанавливает стороннее приложение: Watch Connectivity перестаёт доставлять живые сообщения (`isReachable = false` на iPhone), а вибрацию из приостановленного приложения сыграть нельзя. Обязательный сценарий ФТ-14 «запущенное приложение при автоматически погасшем экране» поэтому не проходил бы. Кроме того, сигнал был одиночным `.notification`: спящий водитель его легко пропускает.

## Как устроено теперь

1. **Фоновая сессия-тренировка.** На время поездки часы держат `HKWorkoutSession` (тип `.other`, без `HKLiveWorkoutBuilder`). Это единственный публичный режим, в котором стороннее приложение часов работает в фоне часами и может играть вибрацию при погасшем экране. Тренировка не сохраняется в «Здоровье»: сессия только завершается. Нужны entitlement HealthKit, `WKBackgroundModes = workout-processing` и разрешение «сохранять тренировки» (запрашивается один раз при первом открытии приложения на часах). Данные здоровья на часах не читаются (СП-01).
2. **Автозапуск с iPhone.** При старте поездки телефон вызывает `wearable.prepare` → `HKHealthStore.startWatchApp(with:)`. watchOS запускает приложение часов даже если оно закрыто, и передаёт конфигурацию в `WKApplicationDelegate.handle(_:)`, где стартует сессия. Дублирующий путь: часы сами стартуют сессию, получив `snapshot` с `level ≠ idle`. Снимок с `level = idle` (конец поездки) завершает сессию.
3. **Повторяющаяся тревога.** Первый импульс по-прежнему решает `AlertGate` (TTL 2 с, отмена, дубли, сверка часов). Дальше `AlarmLoop` повторяет вибрацию раз в 1 с, после 6 с без ответа раз в 0,7 с сильнее, пока событие активно в последнем снимке телефона. Остановка: событие закончилось, `cancel`, кнопка «Я в порядке» на часах (`user_ack`), потеря связи, жёсткий предел 60 с. Рекомендация или проверка дают короткую серию из 3 импульсов. Все числа в `AlarmPattern` (`watchos/NSControlWatch/AlarmLoop.swift`), их подбираем на устройстве.
4. **Сторож связи.** Если во время поездки телефон недоступен 8 с, часы один раз вибрируют и пишут «Связь с iPhone потеряна». Звук телефона от этого не зависит. Через 10 минут без телефона часы завершают фоновую сессию, чтобы не тратить заряд.
5. **Экран часов.** Состояния: нет связи, готово, «Слежу за дорогой» (время в пути, совет), «Камера не видит лицо», красная тревога с одной большой кнопкой «Я в порядке», короткий совет. Отдельной строкой показано, работает ли фоновый режим, и кнопка «Разрешить», если тренировки запрещены. Кнопка «Проверить вибрацию» играет серию локально, без телефона.

## Протокол (совместимые расширения v1)

| Направление | type / поле | Назначение |
|---|---|---|
| часы → телефон | `ready.background` | Состояние фонового режима при рукопожатии |
| часы → телефон | `watch_state` `{background}` | `active` / `starting` / `off` / `denied` / `failed` / `unavailable` при каждом изменении |
| часы → телефон | `ack.watch_received_ms`, `ack.watch_haptic_ms` | Монотонное время часов при приёме и при запросе вибрации, для протокола задержек |
| часы → телефон | `user_ack` (Apple Watch) | Кнопка «Я в порядке», как START на Garmin |
| телефон, канал | `wearable.prepare` | iOS: `startWatchApp`; Android и Garmin: не реализован, ошибка игнорируется |

`haptic_requested` по-прежнему означает только вызов `WKInterfaceDevice.play`, а не физическую вибрацию.

## Сборка и установка

```sh
cd watchos && xcodegen generate
open NSControlWatch.xcodeproj   # Signing: та же Personal Team, что у Runner
```

Если Xcode ругается на HealthKit у цели часов: Signing & Capabilities → + Capability → HealthKit (entitlement уже в `Support/NSControlWatch.entitlements`). Runner пересобрать тоже нужно: в нём новый метод `wearable.prepare`.

Swift-тесты протокола и тревоги (без SDK часов):

```sh
swiftc -module-cache-path /tmp/nscontrol-swift-cache watchos/NSControlWatch/AlertGate.swift \
  watchos/NSControlWatch/AlarmLoop.swift watchos/Tests/main.swift -o /tmp/nscontrol-watch-tests
/tmp/nscontrol-watch-tests
```

## Проверка на устройствах

1. Открыть NSControl на часах, разрешить тренировки. В строке состояния нет «Без разрешения…».
2. На iPhone: «Сон и часы» → «Подключить часы». Ждать «Часы на связи» и «Обмен временем установлен».
3. Начать поездку. На часах «Работает при погасшем экране», в Пункте управления часов виден значок тренировки. На iPhone: «Часы предупредят и при погасшем экране».
4. Опустить руку, дождаться, пока экран часов погаснет (≥ 15 с). На iPhone нажать «Проверить вибрацию часов»: три импульса.
5. Закрыть глаза до тревоги при погасшем экране часов. Ожидается вибрация ≤ 2 с от порога, повтор раз в секунду, затем чаще. Открыть глаза: повтор прекращается. Повторить, но ответить «Я в порядке» на часах: звук телефона тоже прекращается.
6. Закрыть приложение на часах (свайп в Dock) и начать новую поездку: приложение должно запуститься само.
7. Выключить Bluetooth на iPhone во время поездки: через 8 с одна вибрация «Связь с iPhone потеряна», телефон продолжает звук. Включить: связь восстановилась, старые события не вибрируют.

Время начала вибрации подтверждается внешним способом (видео 240 fps рядом с экраном телефона или микрофон на корпусе часов), ПМИ ФТ-14/15. Значения из `ack` только служебные.

## Ограничения

- Пока идёт тренировка, датчик пульса работает чаще, расход заряда выше. Оценить на 60-минутном прогоне.
- Тренировка видна в Пункте управления часов. Сторонние приложения не могут держаться в фоне без неё.
- `startWatchApp` не сработает, если часы далеко или заблокированы. Тогда помогает открыть приложение на часах вручную: сессия стартует по снимку поездки.
