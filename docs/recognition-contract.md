# Контракт распознавания и формат записи (MVP, 25.11.2026)

План и методика: [NSControl — план MVP распознавания](https://claude.ai/artifact/3pSgDXc4yw5zUjhxAcyrtW). Этот файл фиксирует общий контракт для трёх параллельных тредов: «Лаборатория и поток телеметрии», «Движок ARKit», «Методика: зоны взгляда и правила оповещений». Меняется только через PR в `mvp/recognition` с описанием, кто из потребителей затронут.

## Неизменное

- Пороги ТЗ: глаза — обе оценки ниже T не меньше 1,5 с (ФТ-04); голова — наклон относительно калибровки строго больше 20° не меньше 2,0 с при повороте до 30° включительно (ФТ-05). Автоматы `ObservationEngine` получают только `FaceMeasurement`.
- Всё сверх ТЗ (зоны, отвлечение, учёт взгляда вниз) работает под флагом и в режиме приёмки выключается, если оно ослабляет обязательные требования.
- Кадры и видео приложение не сохраняет и не передаёт (ФТ-01), в том числе в Лаборатории и в записи. В запись и поток идут только числа.

## Сигналы лица: `lib/logic/signals.dart`

`FaceSignals` — сигналы одного лица одного кадра в соглашениях водителя. Движок заполняет то, что умеет измерять; `null` значит «не измерено», а не ноль. `DetectedFace.signals` несёт их рядом с прежним `measurement`; `FaceSignals.toMeasurement()` даёт вход автоматов ТЗ.

| Поле | Единицы и знак | ML Kit | ARKit |
|---|---|---|---|
| `headYawLeft` | градусы, > 0 — голова повёрнута влево от водителя | Euler Y после проверки знака | из `ARFaceAnchor.transform` |
| `headPitchDown` | градусы, > 0 — голова вниз | −Euler X (как сейчас) | из `transform` |
| `headRollRight` | градусы, > 0 — к правому плечу | Euler Z после проверки знака | из `transform` |
| `gazeLeft`, `gazeDown` | градусы, взгляд (голова + глаза) относительно камеры | нет | из `lookAtPoint` и `transform` |
| `eyeGazeLeft`, `eyeGazeDown` | градусы, глаз относительно головы | нет | из `leftEyeTransform`/`rightEyeTransform` |
| `eyeOpenLeft`, `eyeOpenRight` | 0..1, 1 — открыт | `leftEyeOpenProbability` | 1 − `eyeBlinkLeft` (или своя проверенная формула) |
| `blendshapes` | 0..1, имена ARKit/MediaPipe, Left/Right — глаз водителя | нет | все 52 или нужные из `Blendshape` |
| `distanceM` | метры до лица | нет | из `transform` |
| `box` | рамка лица {`left`, `top`, `width`, `height`} в долях 0..1 повёрнутого (вертикального) анализируемого кадра, без зеркалирования, начало — левый верхний угол; необязательно | `Face.boundingBox` / размер кадра после поворота | проекция каждой 20-й вершины сетки лица на кадр в портретной ориентации; зеркальность отображения ARKit снимается |
| `tracked` | лицо надёжно отслеживается | true | `isTracked`; при `false` все числа null, чтобы устаревшая поза не попала в автоматы |

Знаки каждого движка подтверждаются на iPhone простым тестом в Лаборатории (повернуть голову влево, опустить, наклонить к плечу, посмотреть глазами влево и вниз) до того, как его значения используются в логике. Текущий знак Euler Y и Z у ML Kit в проекте не проверен.

`GazeZone`: `road`, `mirror_left`, `mirror_right`, `mirror_rear`, `instruments`, `console`, `off_camera`, `unknown`. Решает тред методики; Лаборатория только показывает.

## Запись: JSONL, схема 1

Один объект JSON на строку, UTF-8. Время — целые микросекунды монотонной шкалы от начала записи (`atUs`, `capturedUs`, `completedUs`), календарное время только в `meta`. Файл: `nscontrol-<recordingId>.jsonl`.

```
{"type":"meta","schema":1,"recordingId":"…","app":"1.0.0+2","device":"iPhone12,1","os":"iOS 26.2.1","engines":["mlkit_face_detection"],"startedAt":"2026-11-27T10:00:00+03:00","subject":"S1","notes":""}
{"type":"calibration","atUs":…,"profile":{…CalibrationProfile.toJson()…},"zones":{…ZoneMap.toJson(), необязательно…}}
{"type":"frame","engine":"arkit_face_tracking","capturedUs":…,"completedUs":…,"faceCount":1,"signals":{…FaceSignals.toJson()…}}
{"type":"derived","atUs":…,"zone":"mirror_left","eyes":{…ChannelSnapshot.toJson()…},"head":{…},"fatigue":{…}}
{"type":"event","change":"started","event":{…ObservationEvent.toJson()…}}
{"type":"label","atUs":…,"scenario":"bench-v1","step":"mirror_left","edge":"start"}
```

- `frame` пишется на каждый завершённый анализ. В режиме сравнения двух движков на один `capturedUs` приходится две строки с разными `engine`. Если лица нет, `faceCount` 0 и `signals` отсутствует. Если лиц больше одного, `signals` — лицо, выбранное Лабораторией (откалиброванный trackingId, иначе самое крупное), а остальные идут в необязательное поле `others`: список `FaceSignals.toJson()` в порядке, в каком движок их выдал и конвейер получил. Читатели схемы 1 пропускают незнакомые поля.
- `derived` — то, что приложение решило в этот момент. Программа прогона его не использует: она заново считает решения по `frame`, а `derived` нужен для сверки и для живого экрана.
- `calibration.zones` — раскладка зон внимания `ZoneMap.toJson()` (`lib/logic/attention_zones.dart`): `road` {`headLeft`, `headDown`, `gazeLeft`, `gazeDown`} — абсолютные углы направления «дорога» по голове и по взгляду; `mirrorsCalibrated`; `gazeRegions` и `headRegions` — списки эллипсов {`zone` (код `GazeZone`), `left`, `down`, `radiusLeft`, `radiusDown`} в градусах относительно дороги, знаки как у `FaceSignals`. Поле пишется после калибровки зеркал; без него программа прогона берёт стартовые секторы, а центр дороги по взгляду — медиану взгляда за 10 с калибровки ТЗ.
- `label` — начало и конец шага сценария. Необязательное поле `rep` — номер повтора шага в сценарии (1, 2, …): пара `start`/`end` сопоставляется по `step` и `rep`. Если сценарий прерван, Лаборатория закрывает открытый шаг меткой `end` с полем `"aborted": true`. Метка — эталон для оценки, детектор эталоном не является (ТЗ, методика ПМИ).
- `device` — необязательная строка раз в секунду о телефоне и нагрузке (критерий 4 плана): `{"type":"device","atUs":…,"thermal":"nominal|fair|serious|critical","battery":0.81,"batteryState":"unplugged|charging|full|unknown","lowPower":false,"light":820,"arkitFps":60,"sent":60,"dropped":0,"mlKitDone":28,"mlKitSkipped":32,"mlKitErrors":0,"mlKitBusyUs":700000,"mlKitOrientation":"leftMirrored","imageWidth":1280,"imageHeight":720,"mlKitWidth":640,"mlKitHeight":360}`. `imageWidth`/`imageHeight` — размер `capturedImage` в ориентации сенсора. `mlKitWidth`/`mlKitHeight` — размер кадра, который ML Kit фактически анализировал в режиме сравнения: по умолчанию кадр ARKit уменьшается до ширины 640 с сохранением пропорций (`ArkitOptions.mlKitWidth`, 0 — без уменьшения). Обычный путь ML Kit через плагин camera получает 640×480, то есть 4:3 против 16:9 у ARKit. Поля ARKit и ML Kit есть только у источника ARKit; `light` — `ARLightEstimate.ambientIntensity` (около 1000 при обычном свете). Источник: `ArkitStats.toJson()`.
- `frame` движка ARKit может нести необязательное поле `raw` — числа моста до пересчёта (матрица лица в системе камеры, матрицы глаз, `lookAtPoint`, исходные имена blendshapes, вектор «вверх», флаги `ArkitAxes`), без пикселей. По нему углы можно пересчитать офлайн, если проверка знаков потребует поправить соглашения. Источник: колбэк `onRaw` у `ArkitFaceSource`.
- Неизвестные поля и типы строк читатели пропускают; несовместимое изменение повышает `schema`.

Поток в браузер на Mac передаёт те же объекты (WebSocket, по одному JSON на сообщение).

## Шаги сценария

| `step` | Что делает человек | Ожидаемое событие |
|---|---|---|
| `road` | смотрит на дорогу, моргает как обычно | нет |
| `mirror_left`, `mirror_right`, `mirror_rear` | короткий осмотр зеркала и возврат | нет |
| `blind_spot_left`, `blind_spot_right` | проверка слепой зоны через плечо | нет |
| `intersection_scan` | несколько поворотов влево-вправо, в том числе долгих | нет |
| `instruments` | короткий взгляд на приборы | нет |
| `talk`, `laugh`, `squint`, `yawn` | разговор, смех, прищур, зевок | нет |
| `eyes_closed_1s` | закрыть глаза на 1 с | нет (короче порога) |
| `eyes_closed_2s`, `eyes_closed_3s` | закрыть глаза на 2 и 3 с, голова прямо | `eyes_closed` |
| `head_down_3s` | опустить голову больше чем на 20° на 3 с | `head_pitch_down` |
| `nod` | короткий кивок и возврат | нет |
| `glasses`, `dark` | очки; приглушённый свет | по основному шагу |
| `sign_head_left`, `sign_head_down`, `sign_roll_right` | повернуть голову влево, опустить, наклонить к правому плечу (сценарий `signs-v1`) | нет; проверка знаков `headYawLeft`, `headPitchDown`, `headRollRight` |
| `sign_eyes_left`, `sign_eyes_down` | голова прямо, глаза влево, глаза вниз (`signs-v1`) | нет; проверка знаков `eyeGazeLeft`, `eyeGazeDown` |
| `sign_wink_left` | закрыть левый глаз на 2 с, правый открыт (`signs-v1`) | нет (по ФТ-04 нужны оба глаза); проверка стороны `eyeOpenLeft`: у ML Kit `leftEyeOpenProbability`, у ARKit `eyeBlinkLeft` и `leftEyeTransform` |
| `distraction_4s` | 4 с смотреть на телефон или магнитолу, голова и глаза вниз-вправо, как обычно | `distraction` при включённом расширении; по ТЗ нет; `head_pitch_down` допустим, если голова опущена больше 20°, и не считается ложным |
| `neg_natural`, `neg_mirrors`, `neg_blind_spot`, `neg_intersection`, `neg_instruments`, `neg_mixed` | блоки по 10 мин отрицательного часа ПМИ (А.12, таблица А.1), сценарий `pmi-negative-60` | нет; любое событие — ложное (КЧ-03) |

Список можно расширять новыми `step`; ожидание для нового шага задаётся в программе прогона.

Сценарии описаны в `lib/logic/scenario.dart`: `bench-v1` (около 11 мин; дорога, зеркала по 5 раз, слепая зона и перекрёсток по 3, приборы 5, разговор, смех, прищур, зевки, глаза закрыты на 1/2/3 с по 3 раза, голова вниз на 3 с, кивки, отвлечение на 4 с), `signs-v1` (1 мин, проверка знаков) и `pmi-negative-60` (репетиция отрицательного часа ПМИ А.12: шесть блоков по 10 мин с меткой на блок и редкими подсказками). Метка `start` ставится в момент голосовой подсказки, поэтому реакция человека запаздывает на 0,3–1 с; программа прогона учитывает это допуском ПМИ ± 1 с.

## Движки в Лаборатории и поставщик внимания

- Лаборатория получает результаты через потоковый интерфейс `FaceSource` (`lib/services/face_source.dart`): `engines` (первый — основной, по нему калибровка и автоматы ТЗ), `start(nowUs, onResult, onError, onChanged)`, `stop`, `preview`, `dispose`. Каждый `FaceResult` несёт `engineId`, `capturedUs`, `completedUs`, лица и размер кадра. Путь «плагин camera + `FaceDetectorPort`» обёрнут в `CameraFaceSource`.
- Время `capturedUs`/`completedUs` у всех источников — по часам `nowUs`, которые передаёт Лаборатория (монотонные микросекунды). Движок со своими часами (ARKit) пересчитывает время кадра на эти часы. В запись идут значения относительно начала записи.
- Режим сравнения — один `FaceSource` с двумя `engines`, который на один кадр присылает два `FaceResult` с одинаковым `capturedUs`.
- Зону и решения логики внимания Лаборатория берёт у `AttentionStateProvider` (`lib/logic/attention.dart`): `reset(CalibrationProfile?)` при новой калибровке, `update(FaceSignals?, atUs)` на каждый кадр основного движка, ответ `AttentionState {zone, details}`. Пока логики нет, работает `UnknownAttentionProvider` (зона `unknown`). Поставщик только показывает и записывает зону; тревоги ТЗ запускают только автоматы.
- В Лаборатории по умолчанию подключён `ZoneAttentionProvider` (`lib/logic/attention_zones.dart`). После калибровки поставщик получает `reset(profile)` и сразу `anchorDriver(последний кадр калибровки, его время)`. Каждый кадр основного движка идёт в `updateFaces(все лица кадра)`, а `ObservationEngine` в обоих режимах получает только `lastMeasurements` конвейера: непрерывность водителя `DriverContinuity` возвращает откалиброванный trackingId после потери лица, в режиме Лаборатории ещё работает затвор глаз. После каждого кадра поставщику ставятся `tzSignActive` и `eyesEventActive = snapshot.eyes.activeEvent != null`. Решение о водителе (`same`, `restored`, `no_face`, `ambiguous`, `different`) пишется в `derived.driver` и показывается на странице; прежняя перепривязка калибровки в Лаборатории убрана. Переключатель «Приёмка / Лаборатория» выбирает `AttentionSettings.acceptance()` (только ТЗ, событий `distraction` нет) или `AttentionSettings.lab`; во время записи он заблокирован, выбранный режим пишется в `meta.attentionSettings`.
- После калибровки ТЗ строка `calibration` несёт `zones`: дорога по нейтрали головы и по медиане взгляда за окно калибровки (если у движка есть взгляд), секторы зеркал стартовые. Кнопка «Зеркала» голосом просит по 2,5 с посмотреть в левое, правое и салонное зеркала; удачная калибровка пишет новую строку `calibration` с `zones.mirrorsCalibrated = true` и начинает новую сессию автоматов. События `distraction` пишутся строками `event` с `DistractionEvent.toJson`.

## Движок ARKit

- Источник — `ArkitFaceSource` (`lib/services/arkit_engine.dart`), варианты Лаборатории `arkitLabEngineOptions()`: `arkit` (`[arkit_face_tracking]`) и `arkit_mlkit` (`[arkit_face_tracking, mlkit_face_detection]`). В варианте сравнения ML Kit Face Detection с теми же настройками, что `MlKitDetector`, анализирует тот же `ARFrame.capturedImage` прямо в нативном мосте; пока ML Kit занят, новые кадры ему не отдаются, как в `FramePipeline`. Пока работает ARKit, плагин camera должен быть остановлен: ARKit сам владеет фронтальной камерой.
- **Время.** `ARFrame.timestamp` и «сейчас» моста — системный uptime iOS в микросекундах. Каждое событие моста несёт время отправки, Dart отмечает время получения по часам `nowUs` Лаборатории. Смещение между часами — минимум «получено − отправлено» за последние 10 с (`ClockMap`, `lib/logic/clock_map.dart`); первая оценка — из ответа на `start`. Отсюда `capturedUs` = время кадра + смещение, `completedUs` = момент, когда мост закончил разбор кадра, + смещение. Ошибка равна самой быстрой доставке за окно (обычно меньше 1 мс), задержка канала в `capturedUs` не попадает, `capturedUs ≤ completedUs ≤ nowUs`. Результат ML Kit того же кадра берёт ровно тот же `capturedUs` из кэша по времени кадра, даже если смещение успело уточниться. Окно в 10 с отслеживает возможный дрейф двух часов (Dart может считать время с учётом сна устройства, uptime — без него).
- **Углы.** Мост передаёт геометрию, а углы считает Dart (`lib/logic/arkit_geometry.dart`), чтобы их проверяли тесты и правка знаков не требовала менять Swift. Направление «к водителю» — ось камеры, на которой лежит лицо; «вверх» — ось камеры, ближайшая к гравитации (подходит и портретный, и альбомный держатель); «вправо» водителя = вверх × к водителю. Голова — по осям лица +z (вперёд) и +y (вверх), крен — относительно горизонтальной рамки с тем же поворотом и наклоном. Взгляд — от середины между глазами к `lookAtPoint`; глаз относительно головы — средняя ось +z двух `eyeTransform` в системе лица (+x — собственное левое лица, по документации Apple).
- **Флаги знаков** `ArkitAxes`: `mirror` меняет знак всех величин «влево/вправо», `swapEyes` меняет местами левый и правый глаз и blendshapes. По умолчанию оба выключены (соглашения Apple). Решение принимается по сценарию `signs-v1` (шаги `sign_*`, в том числе `sign_wink_left` для глаз) и таблице «Знаки» отчёта `dart run tool/engine_compare.dart <file.jsonl>`.
- **Веки.** `eyeOpen = 1 − eyeBlink` того же глаза. `eyeLookDown*` и `eyeSquint*` идут в blendshapes без изменений: отделять взгляд вниз и прищур от сомкнутых век — дело логики внимания.
- **Допустимый ракурс глаз.** `arkitCapabilities.eyeYawLimit` до замера равен 18°, как у ML Kit по ТЗ. Значение по замерам на iPhone 11 (раздел 3 отчёта сравнения) заменит его вместе с новой `version`, потому что профиль калибровки привязан к id, версии и пределу.
- **trackingId** — номер якоря `ARFaceAnchor.identifier`, постоянный, пока ARKit держит якорь. Если ARKit создаст новый якорь после потери лица, номер сменится; водителя тогда узнаёт `DriverContinuity` по `box` и `distanceM`.
