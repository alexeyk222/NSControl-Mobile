# Контракты компонентов

Общий принцип: UI не вызывает детектор или SQLite напрямую для принятия решений. Кадры обрабатывает `FaceDetectorPort`; результат передаётся независимому Dart-ядру. `TripController` управляет поездкой, сеансом, немедленным сигналом и асинхронным журналом. `SleepController` сохраняет происхождение сна и применяет правила к актуальному ответу поставщика независимо от ошибки сохранения.

- [Контракт ядра](domain-api.md): настройки, измерения, калибровка, автомат наблюдения, сон и рекомендации. Время событий — микросекунды от начала сеанса.
- [Контракт хранилища](storage.md): поля SQLite, неизменные снимки, транзакции, checkpoint, удаления и CSV. Календарные поля — ISO 8601 с зоной, монотонные поля — отдельная шкала.
- [Контракт платформ и часов](integrations.md): MethodChannel/EventChannel, нативное чтение сна, discovery, сообщения, snapshot, синхронизация, TTL, отмены и ACK. Часовой протокол использует монотонное время процесса телефона, поэтому контроллер прибавляет начало сеанса к времени его события.

Смена детектора меняет только зарегистрированный адаптер и его метаданные. Подмена шкалы открытия глаз без отдельной проверки калибровки недопустима: контракт требует сопоставимых нормализованных значений, а новая модель проходит сравнительные испытания. Неподдерживаемая возможность возвращает явную недоступность; тестовые doubles находятся только в `test`.
