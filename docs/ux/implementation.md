# Интерфейс NSControl: как устроен код

Версия 1.0 от 26.11.2026. Реализация макетов «NSControl мобильный дизайн» (три оформления: A «Кокпит», B «Компаньон», C «Дорожный знак») на телефоне и на часах. Логика распознавания (`lib/logic`, `TripController`) не менялась: интерфейс только читает её состояние и вызывает её действия.

## 1. Слои

```
lib/ui/
  copy.dart            все тексты экрана (Copy) и голоса (Voice), склонения
  design/              токены макета и тема
    tokens.dart        NsDesign (A/B/C), палитры, шрифты, радиусы, NsMotion
    ns_theme.dart      buildNsTheme(design, brightness), NsTheme.of(context)
  presentation/        чистые функции «состояние → что показать», без виджетов
    trip_view.dart     TripView.from(TripFacts): слово статуса, тон, совет, уведомление
    phone_problem.dart PhoneProblem.of(alertError): сбой самого телефона простыми словами
    readiness.dart     Readiness.from(ReadinessFacts): вердикт и строки «Перед поездкой»
    trip_story.dart    TripStory.build(...): лента поездки, тревоги, паузы, итог

    mount_diagram      схема крепления слева / справа / по центру
    owl                знак «Сова», моргает раз в 4,5 с
    buttons            NsButton, HoldToFinishButton, NsOption, NsSegmented, NsChip
    marks              значки ок / внимание / совет / тревога, глифы
    fit_words          крупный текст, который переносится только между словами
  screens/             экраны сценария
    app_shell.dart     машина стадий: знакомство → перед поездкой → камера → в пути → итог
    onboarding_screen  три шага знакомства
    home_screen        «Перед поездкой» + ссылки на историю и настройки
    pre_trip_tab       вердикт, готовность камеры, часов и сна, «Поехали»
    camera_setup_screen настройка камеры голосом, без касаний
    trip_screen        «В пути»: индикатор, слово, совет, Пауза и «Завершить» (удержание)
    trip_dev_panel     технические строки, только в режиме разработчика
```

Правило: **виджет не решает, что показать**. Решает функция в `presentation/`, у неё есть юнит-тесты. Виджет только рисует результат. Так новое состояние добавляется в одном месте и проверяется без экрана.

## 2. Сценарий и анимации

`AppShell.stageOf(...)` по состоянию поездки выбирает стадию (`ShellStage`). Смена стадии идёт плавным перекрёстным переходом (`fadeThrough`, 420 мс). Внутри стадий:

| Место | Анимация | Зачем |
|---|---|---|
| Знакомство | шаги въезжают сбоку с растворением; маркер на схеме крепления переезжает за 300 мс | видно, что выбор принят |
| Проверка звука | волны от кнопки воспроизведения | понятно, что сейчас звучит |
| Настройка камеры | поиск: бегущая дуга; лицо найдено: заполнение за 5 с; ошибка: короткое покачивание; готово: галочка, 1,4 с «Готово» | водитель не смотрит, но видит ход по краю зрения |
| В пути | индикатор «дышит» 6 с (A, B); через 8 с экран тускнеет до 60 % и прячет кнопки, касание будит | экран не отвлекает ночью |
| «Завершить» | заливка кнопки за 1,2 с удержания | случайное касание не завершит поездку |
| Тревога | появление 250 мс; через 5 с или при эскалации слово пульсирует 1 Гц; исчезает за 0,5 с, но не раньше 2 с | тревога заметна, но не мигает |
| Итог | строки появляются по очереди | итог читается сверху вниз |
| Часы | смена состояния растворением 0,3 с; дыхание индикатора как на телефоне | одно и то же поведение на двух устройствах |

Длительности собраны в `NsMotion` (tokens.dart). При системной настройке «Уменьшить движение» сова не моргает, а индикатор не дышит.

## 3. Что сохранено из логики (договорённости с архитектором)

1. Камера молчит → «Камера недоступна» и «Камера не отвечает, наблюдение остановлено». «Слежу» никогда не показывается без наблюдения (`TripView`, первая проверка).
2. Под индикатором одна спокойная строка; технические строки каналов только в режиме разработчика (`TripDevPanel`).
3. Тревога держится не меньше 2 с (`CalmAlarm`), касание в любом месте подтверждает и выключает сигнал. Экран не задерживает звук и автоматику: он только показывает `snapshot`.
4. Режим разработчика: двойное касание ставит отметку (при `liveDebug` или записи), видна ссылка отладки и строки каналов.
5. Перегрев молчит; в экономичном режиме превью скрыто.
6. `movedText` и `calibrationNote` показываются как уведомление вверху экрана поездки.
7. `alertError` (не запустился звук тревоги или его усиление, упал платформенный вызов, не началась запись или живой дебаг) показывается жёлтой карточкой `ProblemCard` на экране поездки (не скрывается до конца поездки) и перед поездкой (можно скрыть, новая ошибка покажется снова). Заголовок для водителя даёт `PhoneProblem.of`, исходный текст контроллера виден мелко под ним.

## 4. Как добавить…

**Новое состояние поездки.** Добавьте факт в `TripFacts.of`, ветку в `TripView.from` (порядок проверок = приоритет), строку в `Copy`, тест в `test/ui/trip_view_test.dart`. Экран подхватит сам.

**Новое оформление.** Значение в `NsDesign`, палитры светлая и тёмная в `tokens.dart`, шрифт в `pubspec.yaml`. Затем ветки в `IndicatorPainter`, `CalibrationPainter` и `WatchDesign` (на часах). Тест `screens_preview_test` сам прогонит все экраны в новом оформлении.

**Новый текст.** Только в `copy.dart`. `test/ui/copy_test.dart` проверяет запрещённые слова («канал», «сеанс», «порог» и т. п.), длину голосовых фраз (до 8 слов) и что красный цвет есть только в тревоге.

## 5. Проверка

```
flutter test                        # всё, включая сценарий от знакомства до итога
flutter test test/ui/app_test.dart  # сценарий на настоящем TripController с подменной камерой
NSCONTROL_SCREENSHOTS=1 flutter test test/ui/screens_preview_test.dart
                                    # PNG всех экранов в build/previews/<оформление>/
```

`app_test.dart` проходит путь пользователя: знакомство → «Поехали» → лицо найдено без касаний → настройка → «Готово» → «Слежу» → глаза закрыты 2 с → тревога → касание → совет остановиться → пауза и продолжение → короткое касание «Завершить» ничего не делает → удержание завершает → «Будил 1 раз» → «Готово».

Часы в облаке не собираются (нет Xcode). Их собирает и ставит Lab на Mac: `xcodegen` по `watchos/project.yml`, установка через `devicectl` (бесплатный профиль, синхронизация с телефона не принимает).

## 6. Решения по умолчанию (ждут подтверждения)

| Вопрос | Принято |
|---|---|
| Тревога затихает сама, если признак ушёл | да, после 2 с на экране |
| Голосовые подсказки | включены по умолчанию, выключаются в настройках |
| Тревога «отвлечение» | выключена, пока не настроен порог по записям |
| Навигация | три раздела: «Перед поездкой» с ссылками на «Историю» и «Настройки», без нижних вкладок |
| Обращение | на «вы» |

## 7. Чего не хватает в логике (запрошено у потока 4)

- Переключатель голоса выключает только подсказки экрана; фразы самого контроллера («Пауза. Защита выключена», «Продолжаю», «Смотрите на дорогу») звучат всегда.
- Выбор лица из нескольких: сделан (#72 + этот PR) на шаге подтверждения до калибровки; рамки зеркалятся как превью фронтальной камеры.
- Интервал перерыва в настройках: зафиксирован 2 ч.
- Выбор, куда звучит тревога (динамик / наушники): опция убрана из настроек.
- Часы не получают уровень `head_only`: экран W-04 «Слежу за головой» нарисован, но придёт только когда контроллер начнёт его отправлять.
- Заряд и нагрев до поездки: данных нет, строка не показывается.
- «В пути X» считает время с последнего перерыва (`drivingTime`), а не с начала поездки.
