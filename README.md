# NSControl 1.0

Мобильное приложение Flutter/Dart для локального обнаружения длительного закрытия глаз и наклона головы вниз, получения завершённого сна с часов, объяснимых рекомендаций отдыха и локального журнала. Требования — итоговое ТЗ редакции 2.3 от 15.10.2026 в папке `Итоговые документы`; архитектурные решения опираются на ПЗ из той же папки. Численные критерии берутся из ТЗ 2.3, поскольку ПЗ ещё содержит ссылки на старое ТЗ 1.1.

Реализованы приложение Android/iOS, адаптер ML Kit, нативные HealthKit/Health Connect и оповещение, Watch Connectivity, Garmin Connect IQ Mobile SDK, приложения watchOS и Connect IQ. Это исходная реализация для стендовой проверки. Прохождение unit/widget-тестов и сборка не подтверждают физическую задержку, качество распознавания или соответствие на контрольных устройствах. Точный результат проверок текущей поставки — в [docs/verification.md](docs/verification.md).

## Быстрый запуск

Инструменты текущей разработки: **Flutter 3.47.7, Dart 3.13.5**, JDK 17, Android SDK/Build Tools 36. Точные версии библиотек зафиксированы в `pubspec.lock`; базовый `google_mlkit_face_detection` закреплён на **0.15.1**. Android minSdk 26, iOS deployment target 15.5. Возможности Health Connect проверяются отдельно от минимальной версии Android.

Если SDK уже установлен:

```sh
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter run -d <device-id>
```

В этой рабочей папке Flutter установлен из официального репозитория в игнорируемый `.tooling/flutter`; JDK и Android SDK также находятся внутри `.tooling`. Они не являются частью исходного репозитория. Для воспроизводимой проверки:

```sh
bash tools/verify.sh
bash tools/build_android.sh --target-platform android-arm64
```

`build_android.sh` использует локальные инструменты, если они есть, иначе ожидает настроенные Flutter/JAVA_HOME/ANDROID_HOME. Проверенная сборка предназначена для ARM64 (Huawei Pura 70). Release APK: `build/app/outputs/flutter-apk/app-release.apk`. По умолчанию локальная стендовая сборка подписывается отладочным ключом; перед передачей постоянного установочного комплекта задайте собственную подпись. Пароли и ключи в Git не добавляются.

Android-устройство: включить режим разработчика и отладку USB, подтвердить доверие компьютеру, затем `adb devices` и `flutter devices`. Установить APK через `adb install -r build/app/outputs/flutter-apk/app-release.apk`. Телефон может потребовать разрешить установку через USB. Камера впервые запрашивается при начале поездки; микрофон не используется. Перед наблюдением проверить звук/вибрацию и выполнить калибровку при закреплённом телефоне.

## Apple и Garmin

Полные инструкции, сообщения протокола и зависимости: [docs/integrations.md](docs/integrations.md).

- **iOS:** нужен полный Xcode, совместимый SDK и подпись. `flutter build ios --release --no-codesign` проверяет сборку без установки; `open ios/Runner.xcworkspace` — настройка Team и установка на iPhone. Проверить HealthKit capability, read sleep permission и разрешение камеры. На данном Mac при начале разработки был только Command Line Tools; наличие Swift CLI не заменяет iOS/watchOS SDK.
- **watchOS:** исходники в `watchos/NSControlWatch`, проект описан `watchos/project.yml` для XcodeGen. Приложение имеет companion bundle ID `org.nscontrol.nscontrol`; его нужно добавить/встроить в проект iPhone согласно инструкции интеграций и подписать той же Team. Установку на Watch проверять отдельно. Наличие исходников не подтверждает работающий фон или экран в погасшем состоянии.
- **Garmin:** `garmin/manifest.xml`, `garmin/monkey.jungle`, `garmin/source`. Требуются официальный Connect IQ SDK, профиль `fenix7x`, локальный developer key и установка `.prg` на часы. Android SDK 2.2.0 выполняет реальный discovery и обмен через Garmin Connect. UUID приложения одинаков в Android и manifest часов.
- **Сон Garmin на Huawei:** реализован путь Garmin Connect → Health Connect → NSControl. Его доступность на фактическом Huawei Pura 70 остаётся предметом обязательной проверки. При недоступности показывается ошибка; ручные/демонстрационные данные не подменяют интеграцию. Garmin Health API не считается предоставленным ресурсом и не подключается к несуществующему серверу.

## Что делает приложение

Вкладки «Поездка», «Сон и часы», «Журнал», «Настройки». Русский интерфейс, светлая/тёмная/системная тема, адаптация к горизонтальной ориентации. Старт: начать поездку, подтвердить единственное лицо и пройти 10-секундную калибровку. Самооценку можно пропустить с явным состоянием «Не оценивал».

Каждый сеанс сохраняет настройки и калибровку. Глаза и голова анализируются независимо; поворот в сторону не вызывает тревогу. Нет очереди кадров, видео не записывается. Сворачивание/блокировка/прерывание останавливает камеру. Старые ответы не применяются к новому сеансу. Звук телефона не ожидает SQLite и часы.

Сон нормализуется по одному выбранному источнику, с объединением пересечений и исключением бодрствования/нахождения в постели без сна. Успешное чтение не доказывает полноту суток. Подтверждение полноты относится к конкретным данным и границам окна; при сдвиге окна проверяется заново. Происхождение с часов сохраняется и показывается; неизвестное или смешанное происхождение не используется для подтверждения полноты. Отсутствие сна не трактуется как ноль часов. Чувствительные данные экспортируются только отдельным выбором пользователя.

Приложение описывает наблюдаемые признаки и ограничения данных; оно не ставит диагноз, не подтверждает бодрость и не рассчитывает безопасное время вождения. Испытания выполняются на неподвижном стенде/в неподвижном автомобиле.

## Архитектура и замена движков

- `lib/logic`: независимое от Flutter ядро, калибровка, автоматы, сон и правила.
- `lib/services`: камера, ML Kit, жизненный цикл, платформенный мост, протокол часов.
- `lib/data`: SQLite schema 1, журнал, CSV, итоги, удаление и восстановление.
- `lib/ui`: реальные экраны и действия пользователя.
- `android`, `ios`: Kotlin/Swift платформенные реализации.
- `watchos`, `garmin`: приложения часов и защита от просроченных команд.
- `test`, `test_tools`: модульные, интеграционные и UI-тесты; `tools/score.py`: оценка независимо размеченных испытаний.

`FaceDetectorPort` получает нормализованный `VisionFrame`, возвращает `DetectedFace/FaceMeasurement` и публикует `DetectorCapabilities` (ID, версия, рабочий ракурс). `DetectorRegistry` создаёт выбранный адаптер в composition root; бизнес-логика не знает ML Kit. Новый движок реализует этот порт и регистрируется в `main.dart`. Он должен нормализовать направление pitch, обеспечить совместимые значения либо собственную проверенную процедуру калибровки и пройти сравнительные испытания. Существующий профиль другого движка не переиспользуется. MediaPipe не выдан за протестированный альтернативный движок: конкретный адаптер добавляется после измеримого обоснования замены.

[Архитектура](docs/architecture.md) · [API ядра](docs/domain-api.md) · [SQLite/CSV](docs/storage.md) · [Приёмка](docs/acceptance.md).

## Проверка и упаковка

```sh
bash tools/verify.sh                 # форматирование, анализ, Flutter и Python
bash tools/verify.sh --android       # дополнительно release APK
python3 tools/score.py --help        # независимая разметка и журнал
python3 tools/package_release.py --output dist/NSControl-1.0-source.zip
```

Упаковщик создаёт воспроизводимый архив, `MANIFEST.json` и `SHA256SUMS`. Он включает исходники, инструкции, итоговые нормативные документы и существующий release APK, исключает инструменты/кэши, ключи, сертификаты, черновики документов и пользовательские базы. Не перезаписывает существующий архив. Для передачи повторно выполнить проверки и сверить SHA-256.

Сборка и исходники должны храниться в репозитории команды с историей и отдельным тегом принятого комплекта. Ответственный, согласованный срок и место архивного хранения ещё не назначены в исходных материалах; это организационные поля приёмки, не подтверждённые свойства реализации. Закрытые испытательные видео и согласия не включаются в исходный комплект.

Лицензии сторонних компонентов доступны через `flutter pub deps`, страницы пакетов и файлы LICENSE зависимостей. ML Kit, Apple SDK, Garmin SDK и Android SDK имеют собственные условия. В приложении не используются облачные API NSControl, аналитика или серверная передача пользовательских данных.
